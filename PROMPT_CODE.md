## 3. Скролл: «следующая глава только после полного прохождения предыдущей»

Это главная механика сайта.

**Каркас.** Lenis (плавный скролл) + GSAP ScrollTrigger. Каждая глава — `<section>`, которая **пинится** на всю высоту экрана. Длина пина — «бюджет скролла» главы (см. таблицу в разделе 4). Пока прогресс главы меньше 1, следующая глава физически не видна: она лежит под текущей (`position: fixed` стек или `z-index`) и закрыта `clip-path: inset(100% 0 0 0)`.

**Переход** запускается, когда прогресс главы = 1. Сначала проигрывается «выход» текущей главы: контент уезжает вверх с маской, 3D‑объект делает финальное движение. Затем новая глава раскрывается через `clip-path` (снизу вверх, 900 мс, `expo.inOut`). Её 3D влетает из глубины. Переход привязан к скроллу (scrub), а не к таймеру. Реверс при скролле назад работает так же красиво.

**Индикатор главы.** Номер «01 / 08» и тонкая полоса прогресса главы в углу. Он нужен, чтобы человек понимал, что глава ещё не закончилась. Это функция, а не декор.

**Клавиатура.** ↓, PgDn, Space листают на следующий «бит» главы. Глубокие ссылки `#chapter-03` работают.

**Тач.** Нативный скролл с Lenis `syncTouch`. Никаких перехватов, ломающих iOS.

## 4. 3D: один WebGL‑мир, глава за главой

**Сцена.** Один fixed‑canvas three.js на весь экран, за DOM‑текстом. Общий рендерер, камера и свет; у каждой главы своя группа объектов. Невидимые группы: `visible=false` и без апдейтов.

**Окружение.** `RoomEnvironment` + PMREM. Сверху `RectAreaLight`: белый key, длинный strip слева (полоса на хроме), ультрамариновый rim сзади‑слева, светло‑ультрамариновый rim справа‑снизу. Это тот же риг, что в Blender.

**Пост‑обработка:** лёгкий bloom (threshold высокий, strength ≈0.35), виньетка, тонкое плёночное зерно. Всё сдержанно и дорого, без кислотного свечения.

**Общие правила движения:**
- Всё управляется прогрессом скролла главы через `gsap.utils.interpolate` и лерпинг с демпфингом (0.08–0.12): движение инертное, «тяжёлое», как у настоящих предметов.
- Курсор слегка наклоняет активный объект (±6°) с инерцией.
- 3D никогда не перекрывает текст. Объекты анимируются в свободных зонах композиции из Figma, позиции бери из скриншотов фреймов.

## 5. Техника

**Стек.** Vite + vanilla JS (без фреймворков) или один `index.html` + `css/` + `js/` с ES‑модулями. three.js (r170+), GSAP + ScrollTrigger, Lenis — через npm или CDN (jsdelivr / unpkg).

**Структура:**
```
index.html
css/style.css
js/main.js
js/scroll.js        — Lenis + ScrollTrigger, пины, гейтинг глав
js/world.js         — рендерер, свет, пост, цикл
js/chapters/00-hero.js … 08-final.js  — каждая глава экспортирует { group, enter, update(progress), exit }
js/lib/vinylNormal.js  — генерация бороздок
assets/models (копия web3d)
assets/posters (копия renders/objects)
```

**Производительность:**
- Повторяющиеся предметы только через `InstancedMesh`.
- `renderer.setPixelRatio(min(dpr, 2))`.
- Модели грузятся лениво: текущая глава + следующая.
- `microphone.glb` прогони через `gltf-transform` (Draco или meshopt).
- Цель: 60 fps на MacBook M1. На мобиле упростить пост, сократить инстансы.
- Нет WebGL или низкий fps → постеры PNG с CSS‑параллаксом.

**Доступность:**
- Весь текст — настоящий DOM, не картинки и не canvas.
- `prefers-reduced-motion`: без пинов, обычный скролл, постеры вместо 3D, только fade.
